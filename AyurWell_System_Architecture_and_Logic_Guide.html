1. Log In and Sign Up (Authentication & OTP Verification) Module

1. Working Flow
User submits registration or login data; backend verifies credentials, coordinates 6-digit cryptographic OTP generation via Java SecureRandom, sends real email verification via SMTP, and returns a signed JWT upon completion.
2. Programmatic Logic
Enforces 30-second cooldown rate limiting, 5-minute OTP Time-To-Live (TTL), maximum 5 failed attempts per OTP lifecycle, and BCrypt one-way password/OTP hashing before persistence in database.
3. Ayurvedic Principle
Prajnaparadha (Intellectual Integrity) & Shaucha (Purity): Clean boundary establishment where individual identity and personal biological profile are protected, maintaining user trust and ethical medicine standards.

A. Step-by-Step Working Mechanism

  1. User Registration (POST /api/v1/auth/register): Receives email, password, fullName, age, gender, height, weight, activity level, and budget. The service checks email uniqueness. It encodes the plaintext password using BCrypt and persists the new User and blank UserProfile in a single transactional unit (@Transactional).
  2. OTP Generation & Dispatch (POST /api/v1/auth/send-otp): Initiated during user verification or password resets. Validates the email format. Queries the latest OTP in email_otps; if requested within 30 seconds, it throws a rate-limit exception. Otherwise, it generates an integer between 100000 and 999999 using java.security.SecureRandom. The OTP is hashed via BCrypt and saved with a 5-minute expiry timestamp. An HTML email with the raw OTP is sent via Gmail SMTP.
  3. OTP Verification (POST /api/v1/auth/verify-otp): Validates length and format. Retrieves the latest record. If attempts >= 5 or current time is past expiresAt, execution is halted with specific user alerts. If passwordEncoder.matches(rawOtp, otpRecord.getOtpHash()) evaluates true, the OTP is marked verified and the user's emailVerified status is permanently activated.
  4. Login Authentication (POST /api/v1/auth/login): Verifies existence of email in the user table. Validates credentials via passwordEncoder.matches(...). Upon success, checks whether the user's health profile and dosha questionnaire are completed. Synthesizes a signed JSON Web Token (JWT) with user ID and email claims, returning an AuthResponse containing JWT, user identity, dosha status, and an AyurScore.

2. Dosha Assessment (Prakriti Determination) Module

1. Working Flow
Presents standardized CCRAS (Central Council for Research in Ayurvedic Sciences) questions capturing physical, physiological, and psychological traits. Computes dominant and secondary constitutional doshas.
2. Programmatic Logic
Aggregates categorized responses into Vata, Pitta, and Kapha accumulator variables; applies tie-breaker hierarchy algorithms; calculates relative percentages; maps tailored herb and lifestyle regimens.
3. Ayurvedic Principle
Tridosha Siddhanta (Tri-Bioenergy Doctrine): Vata (Ether + Air), Pitta (Fire + Water), and Kapha (Water + Earth). Determines Deha Prakriti (inborn genetic blueprint) to identify vulnerability to imbalances (Vikriti).

A. Step-by-Step Working Mechanism

  1. Questionnaire Delivery & Submission: The client requests diagnostic questions evaluating physical build (skeletal frame, skin texture, hair, teeth), physiological tendencies (digestion, appetite, temperature tolerance, bowel habits), and psychological traits (memory, stress response, emotional patterns).
  2. Score Aggregation: Each answer maps strictly to VATA, PITTA, or KAPHA. DoshaAssessmentService.calculateAndSavePrakriti() iterates through all submissions, incrementing respective score tallies ($V$, $P$, $K$).
  3. Primary & Secondary Classification Algorithm: Determines the dominant bio-energy through comparative priority. A distinct secondary dosha is identified by evaluating the runner-up score, recognizing dual-dosha phenotypes (e.g., Pitta-Vata or Vata-Kapha).
  4. Profile Persistence & Dynamic Advice: Saves assessment in dosha_assessments table with timestamp. Updates user_profiles.primary_dosha and sets profile_completed = true. Returns customized dietary rules, lifestyle guidance (Dinacharya), and classical herbs.

B. Mathematical Logic & Dominance Equations

3. Disease Diet Planner (Therapeutic Nutrition) Module

1. Working Flow
Synthesizes biometric traits, dosha prakriti, target clinical diagnosis, season, budget, and meal slots to generate an evidence-based 7-day personalized meal plan with real nutritional analytics.
2. Programmatic Logic
Mifflin-St Jeor BMR & TDEE calculation with disease-specific caloric adaptations; multi-day slot mapping (Breakfast, Lunch, Dinner, Mid-Meals); macro and micronutrient averaging; recipe swap engine.
3. Ayurvedic Principle
Pathya-Apathya & Shad Rasa (Six Tastes): "When diet is wrong, medicine is of no use; when diet is correct, medicine is of no need." Balances Virya (potency), Vipaka (post-digestive effect), and Jatharagni.

A. Step-by-Step Working Mechanism

  1. Requirement Ingestion: Receives target disease condition (e.g., Diabetes/Madhumeha, Hypertension/Raktachapa, GERD/Amlapitta, Obesity/Medoroga, Anemia/Pandu), season (Ritu), budget, allergies, and included meal slots.
  2. Caloric Need Calculation (BMR & TDEE): Calculates Base Metabolic Rate using weight ($kg$), height ($cm$), age, and biological sex, multiplied by the physical activity coefficient, adjusted for clinical parameters (e.g., $-300$ kcal for Obesity).
  3. Therapeutic Slot Selection & Recipe Assembly: Retrieves compliant recipes mapped to the user's primary dosha and clinical condition from the repository. Each meal provides calories, protein, carbs, fats, dietary fiber, iron, calcium, vitamin B12, vitamin D, and folate.
  4. Clinical & Ayurvedic Parameter Synthesis: Generates the AyurScore (0-100), contra-indicated foods to avoid (Apathya), clinical tips, and specific pharmacodynamic properties (Rasa, Guna, Virya, Vipaka).

4. Women's Health & Menstrual Harmony Module

1. Working Flow
Logs daily cycle parameters, period flows, cramps, mood, and iron intake. Dynamically predicts the active menstrual cycle phase, calculates next period dates, and outputs tailored reproductive phase nutrition.
2. Programmatic Logic
Modulo temporal arithmetic (daysPassed % cycleLength) + 1; four-phase cycle segmentation; daily wellness score algorithm (0-100); dedicated stages for Menstruation, PCOS, Pregnancy (Trimesters 1-3), Postpartum, and Menopause.
3. Ayurvedic Principle
Stri Roga & Prasuti Tantra (Ayurvedic Gynecology): Guided by Rajaswala Paricharya (menstrual regimen), Garbhini Paricharya (antenatal regimens), Sutika Paricharya (40-day postpartum restorative healing), and Apana Vayu regulation.

A. Step-by-Step Working Mechanism

  1. Cycle Math & Real-time Phase Estimation: Computes the elapsed days between lastPeriodDate and LocalDate.now(). Using the user's customized cycle length (default 28 days), it derives the exact cycle day and next estimated cycle onset.
  2. Four-Phase Menstrual Segmentation:
    • Days 1 to Period Duration (e.g., Days 1–5): Menstrual Phase (Apana Vayu Active). Downward bio-energy cleansing. Emphasizes warm, easily digestible, iron-rich comfort meals.
    • Days (Duration + 1) to (CycleLength/2 - 2) (e.g., Days 6–12): Follicular Phase (Kapha Building). Anabolic estrogen rise, tissue regeneration (Rasa/Rakta Dhatu), seed cycling.
    • Days (CycleLength/2 - 1) to (CycleLength/2 + 2) (e.g., Days 13–16): Ovulatory Phase (Pitta Peak). High metabolic fire (Tejas), peak vitality; requires cooling, hydrating, nutrient-dense nutrition.
    • Days (CycleLength/2 + 3) to CycleLength (e.g., Days 17–28): Luteal Phase (Vata-Pitta Transition). Progesterone phase; prevents premenstrual bloating, cravings, and cramps with magnesium, B6, and grounding herbs.
  3. Dedicated Stage-Wise Reproductive Health Protocols:
    • PCOS Protocol: Clears micro-channel blockages (Srotorodha) using low-GI grains (Jav, Millets), Kanchanar Guggulu, and Spearmint tea to balance androgens.
    • Garbhini Paricharya (Pregnancy Trimesters 1, 2, 3): Trimester 1 calms nausea and supports cellular folate; Trimester 2 emphasizes blood building (Rakta) and bone minerals (Asthi) via A2 Ghee and Ragi; Trimester 3 prepares the pelvic floor and calms Apana Vayu.
    • Sutika Paricharya (Postpartum Recovery): Rekindles depleted Agni, supports healthy lactation (Stanyajanana) with Shatavari and Methi laddoos, and grounds Vata through gentle Abhyanga and abdominal binding (Udaraveshtana).
    • Menopause Protocol: Replenishes drying Vata, supports bone density (Asthi Dhatu) with white sesame seeds and Praval Pishti (coral calcium), and eases hot flashes.

5. Security Architecture & Protection Mechanisms

1. Authentication Security
Stateless JWT (JSON Web Tokens) signed with HMAC-SHA256, 24-hour expiration token claims, and BCrypt password encryption with adaptive work factor.
2. Transport & Network Defense
Granular CORS configuration restricted to authorized client domains; CSRF disabled for stateless REST APIs; clickjacking defense via Frame-Options.
3. Data & Access Protection
SQL Injection prevention via Spring Data JPA Hibernate parameterized queries; XSS defense via React JSX auto-escaping; brute force OTP protection.

B. Comprehensive Security Components Used

Security Layer Technology / Component Used Exact Implementation Details Threat Mitigated
Credential Hashing BCryptPasswordEncoder Uses adaptive multi-round hashing with automated cryptographic salt generation. Applied to both user login passwords and temporary email OTPs. Credential leaks, Rainbow Table attacks, brute-force dictionary attacks.
Session & Token Handling jjwt-api 0.11.5 (HS256) Stateless authorization. Tokens are signed with a 256-bit cryptographic secret key (Keys.hmacShaKeyFor) with a strict 24-hour expiration (86,400,000 ms). Session hijacking, horizontal privilege escalation, server memory bloat.
Request Filtering JwtAuthenticationFilter Extends OncePerRequestFilter. Intercepts incoming requests, parses Authorization: Bearer <jwt>, checks validity, and sets UsernamePasswordAuthenticationToken in SecurityContextHolder. Unauthenticated resource tampering, token spoofing.
Cross-Origin Security CorsConfigurationSource Explicitly allows trusted origins (http://localhost:5173, http://localhost:3000), requires credentials, and defines whitelisted HTTP verbs and headers. Cross-Origin data theft, unauthorized external cross-domain queries.
Database Query Safety Spring Data JPA & Hibernate All queries utilize parameterized prepared statements and ORM criteria mapping. Direct string concatenation for SQL commands is strictly avoided. SQL Injection (SQLi) attacks.
OTP Abuse Defense EmailOtpService (1) 30-second cooldown rate limit between OTP requests.
(2) Strict 5-minute expiry.
(3) Maximum 5 failed verification attempts before permanent OTP invalidation.
(4) Email masking in responses (e.g. sn***@gmail.com).		 OTP Brute Force, SMS/Email spamming, credential enumeration.
Clickjacking Protection Spring Security Headers Frame options are controlled via headers.frameOptions(frame -> frame.disable()) for local H2 console access while maintaining route-level safety. UI Redress / Clickjacking exploits.
